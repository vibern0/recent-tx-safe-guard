# Native Single-Safe ERC-4337 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Client-only Sepolia vault; one Safe, passkey-only factors, sponsored setup/spending, public delayed queue and manual execution.

**Architecture:** Validation creates one locked Safe with shared WebAuthn owner. Execution deploys credential signers/components and activates the same Safe atomically. Restricted handler uses ordinary owner execution or direct ready-Delay execution; final guard owns policy.

**Tech Stack:** Safe `1.5.0`, passkey `0.2.0`, Delay `1.1.1` pinned source, EntryPoint `0.8.0`, viem `2.56.7`, Hardhat, strict bundler/tracer, React/Vite, SimpleWebAuthn browser `14.0.0`, IndexedDB.

**Spec:** [2026-10-17 native design](../specs/2026-10-17-native-safe-4337-design.md). User accepted design direction on 2026-10-19. Written execution plan awaits review. Preserve earlier requested subagent execution and PR/merge-if-green authorization.

## Global Constraints

- Sepolia `11155111` only. Security research/testnet prototype. No mainnet or production/audit claim.
- One asset-holding Safe. Primary sole owner, threshold `1`; distinct contract/passkey secondary guard-only. No auxiliary account, user/app EOA, relay key or WalletConnect.
- Final guard in both slots. Delay only module; Safe its owner/avatar/target/only proposer.
- Preserve exact SafeTx binding, `0 < X < Y`, shared per-token Y, per-transaction limits, rollback, cancellable Z, delayed weakening and independent non-authorizing monitoring.
- Native/selected ERC-20 `transfer` only on instant paths. Deny batches, delegatecalls, approvals, Permit/Permit2, arbitrary messages and unknown calldata. Fixed bootstrap delegatecall only while locked.
- Sponsored gas only. No vault prefund, token charge, EntryPoint withdrawal, Safe refund or hidden backend/private provider key.
- First operation: `ready or locked`. Execution failure can preserve deployed locked Safe and advance AA nonce; Safe activation nonce remains `0`.
- Queue and execution are separate onchain transactions. Publish complete proposed action; Z begins at queue block timestamp. Manual sponsored Execute needs primary, no fresh secondary. Public Delay execution remains permissionless. Automation deferred.
- Key `0` EntryPoint nonce. Exact `0.8` hashing and `IAccountExecute` substitution. No 7702, aggregator, stock Safe4337Module or alternate-mempool fallback.
- Factory creates only sender during validation. No policy/clock/token/Delay/pending-handler-state access in validation. Never disable strict tracing to manufacture acceptance.
- Browser persists public descriptors/hashes/journal only. Never persist raw assertions, signatures, signed UserOperations or private/admin keys.
- Old backend-profile accounts stay read-only; no funded-account migration. Keep backend until Task 13 gates pass.
- Update call graph and adversarial tests with each path; dependency review with each security dependency. Pin exact versions/lockfile. Preserve unrelated Codacy edits.

### Initial bounded profile

Implementation limits; review with this plan. Fail closed at bounds; never silently shrink test vectors or widen a failed profile.

| Input | Bound |
| --- | --- |
| Assets | Native plus one selected ERC-20; maximum `2` |
| Recipients | Maximum `4` per asset |
| Authenticator data | Maximum `128` bytes per assertion |
| Exact clientDataJSON / encoded clientDataFields | Maximum `512` bytes each; measure both representations |
| paymasterAndData | Maximum `512` bytes including `52`-byte EP0.8 header |
| Signed validity interval | Finite, maximum `600` seconds; no validation clock read |
| Complete ABI-encoded PackedUserOperation | Maximum `8192` bytes, all dynamic fields included |
| Account/paymaster verification limits | Each at most `499999`; measured usage plus `4000` slack must fit the chosen limit |
| Activation call gas | Project ceiling `8000000`; provider acceptance unproven |
| Runtime / component initcode | At most `24576` / `49152` bytes |

Unsupported authenticator/extension sizes: explicit unsupported-profile error, before signing/submission. Public profile additionally carries finite fee ceilings, sponsor set and per-run total budget; no unbounded/default credential or fee value. Those deployment inputs need reviewed values before quote/submit.

## Review Focus

- Sponsor/fee change between inner and outer signing: invalidate outer approval; no silent mutation. Tasks 2/9.
- Shared signer called without Safe storage context: reject; same-key owner swap and post-rotation signing remain usable. Tasks 3/4/7/9.
- Timeout/reload/two tabs/reorg: one immutable intent; reconcile before replacement, including locked-account retry. Tasks 8/10.
- Public queue missing after approval: wait for actual onchain `TransactionAdded`; never start Z from browser signature time. Tasks 6/11/12.
- Authenticator DER/JSON variation or oversized assertions: exact cryptography or explicit unsupported result; never synthesize signed fields. Tasks 2/9.
